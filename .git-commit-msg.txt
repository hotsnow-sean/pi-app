fix(plugins): 审查批次 1 —— 三个静默错误 + 六条 P2

代码审查（doc/dev/review-plugin-host-2026-11-06.md）里「用户看不见但确实错了」的一批。

P1-1 增量读丢字节：decode() 为避开半个多字节字符会退到最后一个换行，但
nextOffset 仍按「读了多少字节」前进，退回去那段既不在本次文本里也再读不到。
decode 改为返回 { text, bytes }，chunkBytes/nextOffset 按实际消费算。

P1-2 lost 的回报语义自相矛盾：recover() 写 report:'pending' 却从无调度路径送它，
面板于是常挂「待回报」且没有重试入口。改成 skipped + 原因，面板给「重新回报」。

P1-3 每次「停用→启用」泄漏一个订阅：settings.onChange / sessions.onRunEvent 的
解除函数被插件丢掉。PluginInstance 现在持有 disposers[]，buildContext 用 track()
登记，deactivate 统一回收；activate 失败也回收。deactivate 顺带改成 await。

P2-1 入口路径校验改 path.relative（startsWith 挡不住 bg-evil 这类兄弟目录）
P2-2 回报队列 key 走 normSession，原始路径单独存着供投递
P2-3 投递失败写 reportError，不再覆盖 task.error
P2-4 describeStart 的 120ms 窗口内记录被清掉时，回执如实说「已被清理」
P2-5 面板错误横幅在恢复正常时强制重绘，不再永久挂着
P2-6 maxLogMb 文案改成事实（超限是终止任务，不是只截断日志）

测试：插件 43 条（新增增量读 / lost 语义 / reportError），宿主插件层 8 条
（新增 plugin-host-entry，回滚验证过会失败）。
